# Legacy classical-model audit — 2026-09-26

The eight legacy scripts provide useful estimator families, but their data preparation and evaluation should not be reused. A bounded research factory now exposes these families plus the current HistGradientBoosting and MLP models. This audit is source inspection and synthetic API validation; it does not establish financial forecasting performance or justify publishing a new ensemble.

Scope: `C:/DATASTORE/hyperliquid/BERA-EXAMPLE/models/dt/traintesteval/`, its shared classical preprocessing and target generation, and the current model factory. Applicable ancestor `AGENTS.md` paths were checked; none were present. No legacy module was imported or executed. No live model, Paper state, credential, or process was changed by this audit.

| Most searches optimize classification accuracy | Seven scripts leave search `scoring` unset; CatBoost explicitly uses accuracy. Reports mainly use hard predictions and feature importances. None implements a held-out probability calibration block. | Compare probabilistic losses and calibration on aligned timestamps, alongside directional metrics and cost-aware Paper evaluation. The legacy target divides a three-bar future log return by a positive historical volatility estimate. Where defined and positive, this division does not change its sign. It therefore does not create a separate neutral class or, by itself, a more cost-aware target. See [targetval.py:32](C:/DATASTORE/hyperliquid/BERA-EXAMPLE/target/targetval.py:32).

## Minimal reusable implementation

[hyperliquid_research_classical.py](C:/dev/ducketz/ml/hyperliquid_research_classical.py) supplies `make_classical_estimators(seed=42, threads=2)`, returning `(estimators, skipped)`. Each estimator entry contains a fresh raw sklearn-compatible estimator and a `scaled` boolean. The caller owns fit-only preprocessing, timestamp splits, label purging, calibration, model selection, and the outer native-thread limit. The factory itself does not fit models or load data. It never imports the legacy code.

The current logistic, ExtraTrees, HistGradientBoosting, and MLP parameters remain identical to the production factory. The new families are bounded: RandomForest has 128 trees, depth 10 and minimum leaf size 12; AdaBoost has 100 depth-2 trees with minimum leaf size 12; GradientBoosting has 100 depth-3 trees with minimum leaf size 20; LightGBM has 100 trees, maximum depth 6 and 15 leaves; XGBoost has 100 depth-6 histogram trees with L2 regularization. Optional CatBoost has 100 depth-6 iterations, L2 regularization and disabled auxiliary file writing. All explicit estimator worker counts are 1. `threads` validates the caller's intended outer thread budget; the caller must apply that limit.

Only logistic and MLP request standardization. All entries still require finite features or suitable training-fitted imputation. An absent top-level optional package is listed in `skipped`; a broken installed package, missing transitive dependency, or constructor error propagates rather than silently changing the candidate set.

Safe package-metadata inspection of `.venv` found scikit-learn 1.9.0, LightGBM 4.7.0 and XGBoost 3.3.0. CatBoost and scikit-optimize are absent. No packages were installed. The factory therefore exposes **nine available families**, with an explicit CatBoost skip. Neither scikit-optimize nor legacy search scripts are required.

Select additions using the approved aligned research protocol. Adding all candidates to an equal-weight ensemble would itself be a separate change requiring evaluation: several tree ensembles may make highly correlated errors. A successful synthetic fit establishes API compatibility, not improved market performance. Earlier inspected history remains development evidence and must not be described as an untouched test after results have guided choices.
