# Opt-in XNAS minute history prefix extension

The new `ml.stock_target_history --extend-to-feature-history` option keeps the existing `xnas-itch-archive-v1` minute price source. It uses verified native daily/hourly observations to identify only an older uncovered minute prefix. It does not create labels, fit models, blend datasets, or convert seconds into additional minute samples.

The read-only production preview for the September 23 source session requires six prefixes: AAPL, AMZN, COST, GOOG, MU, and NVDA, each from 2019-08-19 through the exclusive existing-minute boundary 2025-01-13. CROX, IONQ, PATH, TWST, and SNDK already cover their actually observed daily/hourly feature histories. SNDK's first feature observation is 2025-02-24; its minute baseline begins 2025-01-13. The complete verified source evidence is in `feature-history-extension-plan-preview.json`.

Acquisition remains inside the existing cold-start process lock. The optional path verifies original current cursors and raw/normalized native partitions, saves the original cursor bytes, validates exact provider bounds, requires fresh finite zero-dollar cost metadata, and applies the native capacity reserve/expansion calculation plus a 20 GB total billable-byte bound. Zero-record required prefixes fail explicitly. The existing native generic writer publishes and verifies each prefix; this path never writes current minute cursors. Rebuilding after a partial completion discovers verified prefix partitions and omits already covered work. Default daily maintenance then proceeds unchanged.

Extension manifests, provider/capacity preflight, progress and failure evidence are run-local. Successful final stock-target-history receipts bind the extension report by checksum. A required extension failure writes a FAILED receipt and never claims the full history is current. This preflight performed no acquisition or provider metadata calls.

Validation: `python -m pytest tests/test_stock_target_history.py tests/test_stock_target_history_fallback.py -q` passed 63 tests. Coverage includes cursor identity preservation, exact observed/IPO floor, corrupt provenance rejection, zero-cost/capacity/provider coverage failures, native publication verification, reuse without new provider calls, receipt binding, and unchanged daily/seasonal fallback behavior. Existing hardcoded seven-symbol test expectations now derive the configured universe.
